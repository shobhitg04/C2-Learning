# Documentation

When a feature changes, update the matching file in spec/ first, then docs/.

## How to write it

- Use short sections.
- Open each section with a lead sentence that states the decision.
- Use a table for options compared.
- Add a "Trade-offs" paragraph for every design choice.

## Checklist

- [ ] spec updated
- [ ] architecture.md updated
- [ ] README run instructions still correct
